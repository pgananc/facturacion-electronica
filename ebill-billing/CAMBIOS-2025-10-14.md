## 1. Corrección de Cálculo de Impuestos (ICE + IVA)

### Problema

El ICE ($31.35) no se estaba sumando al total de impuestos. Solo se calculaba el IVA.

### Solución

**Archivo**: `src/main/java/com/wallparisoft/ebillbilling/service/impl/GenerateInvoiceSri.java`

```java
// ANTES: Solo calculaba IVA
BigDecimal totalImpuestos = invoiceDto.getInvoiceDetails().stream().map(detail -> {
  BigDecimal subtotal = detail.getSubtotal() != null ? detail.getSubtotal() : BigDecimal.ZERO;
  BigDecimal rate = detail.getProductDto().getRate() != null ? detail.getProductDto().getRate() : BigDecimal.ZERO;
  return UtilsMath.iva(subtotal, rate);
}).reduce(BigDecimal.ZERO, BigDecimal::add);

// AHORA: Calcula IVA + ICE
BigDecimal totalIva = invoiceDto.getInvoiceDetails().stream().map(detail -> {
  BigDecimal subtotal = detail.getSubtotal() != null ? detail.getSubtotal() : BigDecimal.ZERO;
  BigDecimal rate = detail.getProductDto().getRate() != null ? detail.getProductDto().getRate() : BigDecimal.ZERO;
  return UtilsMath.iva(subtotal, rate);
}).reduce(BigDecimal.ZERO, BigDecimal::add);

// Agregar ICE si existe en el DTO
BigDecimal totalIce = invoiceDto.getSubtotalIce() != null ? invoiceDto.getSubtotalIce() : BigDecimal.ZERO;

// Total de impuestos = IVA + ICE
BigDecimal totalImpuestos = totalIva.add(totalIce);
```

## 3. Sistema de Reintentos para Scheduled Task

### Problema

- La tarea programada recuperaba facturas inactivas (`status = false`)
- No había límite de reintentos
- No se marcaban como inactivas las facturas con fallos persistentes

### Solución Implementada

#### 3.1. Campo `retry_count` en Invoice

**Archivo**: `src/main/java/com/wallparisoft/ebillbilling/entity/Invoice.java`

```java
@Column(name = "retry_count")
private Integer retryCount;
```

**Migración**: `src/main/resources/flyway/V2025101402__add_retry_count.sql`

#### 3.2. Filtro en Consulta de Repositorio

**Archivo**: `src/main/java/com/wallparisoft/ebillbilling/repository/IInvoiceRepo.java`

```java
@Query(
    "SELECT i FROM Invoice i WHERE "
        + "i.status = true AND "  // ← Solo facturas activas
        + "((i.authorizationSri.receptionStatusSri IS NULL OR ...) "
        + "OR (i.authorizationSri.authorizationStatusSri IS NULL OR ...))")
List<Invoice> findInvoicesExcludingSpecificSriStatuses(...);
```

#### 3.3. Lógica de Reintentos

**Archivo**: `src/main/java/com/wallparisoft/ebillbilling/service/impl/InvoiceServiceImpl.java`

**Comportamiento:**

1. Nueva factura: `retryCount = 0`
2. Primer fallo: `retryCount = 1`, se guarda, se reintenta en 2 minutos
3. Fallos 2-4: Incrementa `retryCount`, sigue reintentando
4. Quinto fallo: `retryCount = 5`, se marca `status = false` (invoice y detalles)
5. Éxito en cualquier momento: `retryCount` se resetea a 0

**Logs con contador:**

```
ERROR - Connection error for invoice 2 (retry 1/5): Connection refused
ERROR - Connection error for invoice 2 (retry 2/5): Connection refused
...
ERROR - Invoice 2 has exceeded maximum retries (5) - Marking as inactive
INFO  - Invoice 2 and its 3 details marked as inactive
```

#### 3.4. Métodos Auxiliares

```java
// Maneja cada fallo
private void handleInvoiceFailure(Invoice invoice, String reason) {
  invoice.setRetryCount(invoice.getRetryCount() + 1);
  if (invoice.getRetryCount() >= 5) {
    deactivateInvoiceAndDetails(invoice);
  } else {
    repo.save(invoice);
  }
}

// Marca invoice y detalles como inactivos
private void deactivateInvoiceAndDetails(Invoice invoice) {
  invoice.setStatus(false);
  if (invoice.getInvoiceDetails() != null) {
    invoice.getInvoiceDetails().forEach(detail -> detail.setStatus(false));
  }
  repo.save(invoice);
}
```
